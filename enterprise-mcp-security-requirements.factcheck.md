# Enterprise MCP security requirements

| ID and principle                        | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **MCP-01 · Governance**                 | Enterprise MCP integrations must be approved before use, inventoried, and assigned an accountable owner. The inventory must cover local and remote hosts and clients, servers, intermediaries, and enabled capabilities, including tools, resources, prompts, and extensions. Record approved uses and data and trust boundaries.                                                                                                                                                                                                                                                                                                           |
| **MCP-02 · Traceability**               | Every enterprise operation performed by an MCP-enabled agent must be attributable across components and downstream systems to an authenticated initiating user or a uniquely identified, authorized workload with an accountable owner. Preserve the executing identity and applicable delegation.                                                                                                                                                                                                                                                                                                                                          |
| **MCP-03 · Authentication**             | Verify caller and service identities and protect channels and credentials according to the transport and trust boundary. Where tokens are used, validate the trusted issuer, intended audience, and validity. Prohibit token passthrough and use credentials intended for the downstream service.                                                                                                                                                                                                                                                                                                                                           |
| **MCP-04 · Authorization**              | Deny by default. Enforce least privilege independently of the AI model on each protected request, checking the capability, action, target resource, tenant where applicable, and the caller’s effective authority.                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **MCP-05 · Human oversight**            | The host must obtain explicit, informed, scoped, revocable user consent before operations in a user context, including data access, tool use, and onward sharing. Honor that scope for deferred work. An authorized human must approve each high-risk action and its material parameters before execution unless an approved policy expressly preauthorizes that action class within documented, time-bounded, revocable limits. Define which actions always require individual approval. Unattended workloads require their own scoped, time-bounded, revocable authorization and must honor applicable consent and approval requirements. |
| **MCP-06 · Data protection**            | Apply enterprise classification, privacy, and information protection requirements throughout the data lifecycle. Minimize data and restrict use and disclosure to authorized purposes and recipients, including model providers and other third parties. Apply retention and deletion rules to stored data, caches, logs, and traces.                                                                                                                                                                                                                                                                                                       |
| **MCP-07 · Input and output security**  | Treat external content and model-generated requests as untrusted, including prompts, resources, tool metadata, and results. Servers must validate inputs and sanitize outputs. Clients must validate results before use. Enforce authorization independently on every resulting action or disclosure.                                                                                                                                                                                                                                                                                                                                       |
| **MCP-08 · Integrity and supply chain** | Use approved sources and verify the provenance and integrity of software, dependencies, configuration, and updates. Control installation and changes, including changes to tool definitions, and reapprove material capability changes before use.                                                                                                                                                                                                                                                                                                                                                                                          |
| **MCP-09 · Isolation**                  | Enforce risk-appropriate isolation across user, service, tenant, and trust boundaries. Cover host and server execution, credentials, context, state, caches, filesystem access, and network access. Restrict outbound connections to approved destinations or destination classes.                                                                                                                                                                                                                                                                                                                                                          |
| **MCP-10 · Security enforcement**       | Enforce applicable enterprise controls on every path the integration or its agents can use to reach protected operations, including direct APIs, alternate endpoints, intermediaries, and downstream service calls. Deny paths where required controls cannot be enforced.                                                                                                                                                                                                                                                                                                                                                                  |
| **MCP-11 · Monitoring and auditing**    | Capture and correlate security-relevant events across components, including denied requests, approvals, and outcomes. Protect records against unauthorized access and tampering, retain them under policy, minimize sensitive content, and monitor for events that require a response.                                                                                                                                                                                                                                                                                                                                                      |
| **MCP-12 · Operational security**       | Enforce resource and workflow limits. Deny protected operations when required controls cannot be verified. Handle retries, interrupted operations, and uncertain outcomes safely. Revoke access within defined deadlines, stop queued work, and maintain tested procedures to contain in-flight work and recover safely.                                                                                                                                                                                                                                                                                                                    |
| **MCP-13 · Security lifecycle**         | Assess and test integrations before production and after material changes. Reassess periodically, manage and remediate vulnerabilities, keep components on supported versions, and retire integrations securely.                                                                                                                                                                                                                                                                                                                                                                                                                            |
