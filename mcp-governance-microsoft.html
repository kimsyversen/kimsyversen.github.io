MCP Governance in a Microsoft ecosystem

A proposed design to make a gateway the only way to reach a company MCP server and to limit managed clients to approved servers, across GitHub Copilot, VS Code, Foundry, Copilot Studio and Microsoft 365 Copilot.

The design

In shortKeep the company MCP server behind the gateway and limit managed clients to approved servers. recommendation

ScopeThis is the released-only design. It uses supported MCP capabilities in the API Management service, subject to tier availability. Preview features are in the other design: select With preview above, or read With preview.

ScopeThis design replaces the API Management service gateway with the separate AI Gateway product, which is in public preview, and adds the Agent 365 integration. Use it only in a sandbox. The released-only design stays underneath. Details and limits are in With preview.

Rollout and tests

GoalAPI Management alone does not guarantee objectives A and B. recommendation

Order of work

  1. First. Inventory MCP use, put the approved list in a repository and build the pipeline that applies it.
  2. Next. Isolate the company MCP backends and require access through API Management.
  3. Then. Add endpoint application control, local server limits and outbound policy.
  4. Finally. Add monitoring, review exceptions and run the bypass tests on a schedule.

Approval and denial workflow

Use two gates: the company's reviewed inventory change, then Microsoft's tenant approval for the preview Agent 365 server route. An approval in one gate does not replace the other. recommendation

  • Who approves. An AI Administrator or Global Administrator, under Agents > Tools > Requests (preview). V186 V187 V87
  • Tool level. Individual tool controls are rolling out for supported Agent 365 servers. BYO server tool-level blocking is planned. Until then, block at server level and authorize at the gateway and backend. V188 V37 V44
  • Revoke. Block the server in the registry, mark it denied in Git, remove it from the target allowlists and verify that calls are denied. Microsoft 365 admin actions do not update the other policy targets. recommendation

This is the MCP server request queue V181. Approval of an agent publication is a separate workflow. The All agents registry is an inventory view; its Data & tools details are read-only and may be missing for some agents. V190 V191 V192 V193

Preview pilot, after the baseline

  1. Scope. Pick a low-risk server with two read-only tools and one controlled write tool. Record owner, data class, sign-in and expected clients.
  2. Resource type. Create the separate AI Gateway product on the current resource type in a supported public preview region V45 V52 V195. Confirm eligibility, the public front door, networking, policy features and licensing.
  3. Lock the backend. Make direct calls fail. Check the supported backend network design, because the new gateway has no private endpoints V47.
  4. Connect Agent 365. For the API Management integration, after named tenant-admin consent, connect the gateway and check that the server shows up. Review the permissions granted V40.
  5. Test blocking. For the preview Agent 365 integration, test server block/unblock on a supported API Management v2 tier. Test tool blocking and threat protection only on the separate AI Gateway product, with a static tool list and a delegated user-token flow V38 V53 V194. Test Audit, Block and failure handling. App-only workloads are not supported V54.
  6. Gate promotion. Require accepted support terms, released features, incident playbooks and a rollback plan before leaving the sandbox V35.
