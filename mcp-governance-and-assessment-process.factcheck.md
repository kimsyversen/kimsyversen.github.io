# Fact check: MCP Governance and Assessment Process

Checked 27 November 2026.

| Claim | Source | Verdict |
|---|---|---|
| About 70% of exposed MCP servers Wiz tested returned their full tool catalog to anonymous callers. | [Wiz Research, “The risk hiding behind exposed MCP servers”](https://www.wiz.io/blog/the-risk-hiding-behind-exposed-mcp-servers), “By the numbers” | Verified. The source describes exposed servers, not all MCP servers, and specifically says they returned the full tool catalog to anonymous callers. |
| The assessment uses four domains from the NHI guide. | [NHI MCP Server Trust Assessment Guide](https://nhimg.org/mcp-server-trust-assessment-guide), domains 1 to 4 | Verified. The guide names identity and authentication, permissions and tool surface, provenance, and change control. The intake's risk tiers, approval authorities and scanning matrix are organizational proposals. |
| Backslash Security provides guidance on endpoint and agent-context risks. | [How to Evaluate an MCP Server's Risk Before Employees Install It](https://www.backslash.security/learning/how-to-evaluate-an-mcp-server-s-risk-before-employees-install-it), “What makes an MCP server risky before anyone installs it?” | Verified as vendor guidance on execution location, inherited credentials, tool permissions and untrusted content. |
| When an MCP client starts a local server with `npx`, it runs code from an npm package. | [npm CLI, npx description](https://docs.npmjs.com/cli/v11/commands/npx/#description) and [MCP local server guide, filesystem server configuration](https://modelcontextprotocol.io/docs/develop/connect-local-servers#installing-the-filesystem-server) | Verified. The MCP guide configures the client to launch the filesystem server's npm package with `npx`. Reusing package review evidence and assessing the server's tools are recommendations. |
| Local server code can read credentials its process can access. | [MCP security policy, stdio trust boundary](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/SECURITY.md#stdio-transport-trust-boundary) and [OWASP MCP Security Cheat Sheet, key risks](https://cheatsheetseries.owasp.org/cheatsheets/MCP_Security_Cheat_Sheet.html#key-risks) | Verified. The deployment environment enforces isolation. Credential exposure depends on the privileges granted to the process. |
| A model can choose tools, and a malicious description from one server can influence its use of a tool from another server. | [MCP tools specification, user interaction model](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#user-interaction-model) and [Invariant Labs, experiments with tool poisoning](https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks) | Verified. The specification permits model-selected calls. Invariant demonstrated cross-server influence with two servers connected to the same client. |
