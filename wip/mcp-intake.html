Stage-by-stage instructions

Process

Nine stages run in order. A failed gate stops the server there. Nothing from the server runs before Sandbox.

  • Data it will reach
  • Tools wanted

3. Pin

Inputs
  • Exact version, image or URL
Actions
  1. Local or container: fetch into quarantine or an internal mirror, record digests, lock the dependency tree and build an SBOM.
  2. Remote: record the URL, the certificate-protected connection and the authorization metadata.
  3. Verify signatures and provenance.
  4. On a change, compare the new local dependency tree and install scripts with the approved ones. For a remote server, record the endpoint details again.
What runs
Only the fetch tool, in a quarantine area. No install scripts.
Output
Digests, lock file, SBOM and provenance result, or the remote endpoint details.
Gate

Automatic approval of a new version

Allow it only when all of these are true. It skips the Review stage, so nobody reads the code difference. The approver for the server's tier approves the rule in advance and is the approver of record. Otherwise a person decides.

  • The server only reads, and only public or non-sensitive data.
  • A local server runs contained, with limited outbound traffic.
  • The publisher, license, launch command, environment variables and install scripts are unchanged, and there is no new dependency, destination or scope.
  • The captured surface is identical.
  • Every check in Screen, Pin, Scan and Sandbox passes, including the 7 day wait. An earlier result from a person counts only if what that person looked at is unchanged.

Decisions

Approve
Released as recorded.
Approve with conditions
Released with limits that the platform or the owner enforces, such as fewer tools, fewer scopes, named users or a sandbox.
Reject
Added to the deny list when the reason is malicious or impersonation.
Defer
Nothing is released until the missing evidence arrives.
