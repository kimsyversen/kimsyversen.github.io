Which VS Code safeguards stop an AI agent?

Workspace Trust determines whether an agent can start. Once it starts, approval rules determine when it needs your permission. Sandboxing limits the files and network destinations a covered process can reach.

Approval and sandboxing

Approval

“Can this action run without asking for confirmation?”

A one-time approval covers the current request. A saved approval can cover later requests within its scope.

Sandbox

“Which resources can this covered process access when it runs?”

The sandbox limits a command while it runs, also after you said yes.

These examples use the Copilot harness in editor chat with its default tools and a local Unix shell. They assume no prior grants or organization policy. When allowed, the example agent requests a one-time retry outside the sandbox, without first offering path approval. The MCP example uses a workspace-configured server started by VS Code, with the default chat.agent.sandbox.mcpServers setting. Per-server MCP sandboxing is a separate feature and is not modelled. The MCP example also ignores the sandbox network setting and the request to run outside the sandbox.

Six steps the VS Code docs recommend

  1. Review a project before trusting it.
  2. Confirm the session’s workspace and execution environment.
  3. Choose an appropriate permission level.
  4. Restrict command access and verify it.
  5. Limit tools and credentials to the task.
  6. Review changes before integrating them.
