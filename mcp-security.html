MCP Security

MCP (Model Context Protocol) is a set of rules that lets an AI app use other programs, called MCP servers. A server can give the app tools (things it can do, like search the web), resources (things it can read, like a file) and prompts (ready-made instructions). A server runs on your computer or on another one.

MCP servers are installed the same way as other npm packages

A malicious MCP server can use the same access as your other software

It can do these things without the AI invoking a single MCP tool. Execution of the server itself is sufficient.

MCP therefore introduces additional AI-specific attack surfaces on top of traditional software supply chain risks.

Local, remote and bridged servers carry different risks

Local MCP

Client and server run on the same machine, with the same privileges unless the server is isolated.

Local code execution risk

Remote MCP

Server code runs on another machine. Unlike a local server, it does not need installing on each device.

No direct local server execution

Remote through a local bridge

The bridge is local software. One bridge, mcp-remote, had a command injection flaw.

Local software can have flaws

A remote server is still an MCP server. OWASP names data exfiltration, servers acting with broader rights than the user, prompt injection and tool poisoning among MCP risks.

Control both which code runs and what the AI can access [recommendation]

Limit npx as well as MCP servers: npx can run any command from an npm package.

MCP governance should extend existing software supply chain and endpoint security controls, not replace them.

13 principles for using MCP securely [recommendation]

  1. Only approved, inventoried, and owned MCP servers may be used.
  2. All agent actions must be traceable to a human user or accountable workload owner.
  3. All MCP connections must use secure authentication, communication, and credential management.
  4. Agents and MCP servers must operate with least privilege.
  5. Sensitive tool actions must require appropriate authorization and human approval where necessary.
  6. Data accessed or transmitted through MCP must comply with organizational data protection requirements.
  7. Untrusted content must not override security policies or execution boundaries.
  8. MCP servers, tools, and dependencies must be trusted and protected against tampering.
  9. MCP execution must be isolated within controlled system and network boundaries.
  10. MCP interactions must not bypass established security controls.
  11. All MCP activities must be logged, monitored, and auditable.
  12. MCP operations must enforce resource limits, support revocation, and fail securely.
  13. MCP integrations must undergo security assessment, testing, and ongoing lifecycle management.
