Two governance layers [recommendation]

Restricting MCP servers while permitting unrestricted npx leaves the arbitrary code execution risk in place.

MCP governance should extend existing software supply chain and endpoint security controls, not replace them.

“Execute MCP server commands in a sandboxed environment with minimal default privileges” MCP security best practices

Security and governance principles [recommendation]

  1. Only approved, inventoried, and owned MCP servers may be used.
  2. All agent actions must be traceable to a human user or accountable workload owner.
  3. All MCP connections must use secure authentication, communication, and credential management.
  4. Agents and MCP servers must operate with least privilege.
  5. Sensitive tool actions must require appropriate authorization and human approval where necessary.
  6. Data accessed or transmitted through MCP must comply with organizational data protection requirements.
  7. Untrusted content must not override security policies or execution boundaries.
  8. MCP servers, tools, and dependencies must be trusted and protected against tampering.
  9. MCP execution must be isolated within controlled system and network boundaries.
  10. MCP interactions must not bypass established security controls.
  11. All MCP activities must be logged, monitored, and auditable.
  12. MCP operations must enforce resource limits, support revocation, and fail securely.
  13. MCP integrations must undergo security assessment, testing, and ongoing lifecycle management.
