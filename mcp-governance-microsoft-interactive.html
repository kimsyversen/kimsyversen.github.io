The design

In shortKeep the company MCP server behind the gateway and limit managed clients to approved servers. Map the approved inventory into each policy target, because visibility alone does not enforce access. recommendation

ScopeThis is the released-only design. It uses supported MCP capabilities in the API Management service, subject to tier availability. Preview features are in the other design: select With preview above, or read With preview.

ScopeThis design adds the Agent 365 integration and lets the separate AI Gateway product, which is in public preview, replace the API Management service gateway. Use it only in a sandbox. The released-only design stays underneath. Details and limits are in With preview.

ObjectivesA means company backend access through the gateway only. B means restricting managed clients to approved MCP servers.

Rollout and tests

Order of work

  1. First. Inventory MCP use, put the approved list in a repository and build the pipeline that applies it.
  2. Next. Isolate the company MCP backends and require access through API Management.
  3. Then. Add endpoint application control, local server limits and outbound policy.
  4. Finally. Add monitoring, review exceptions and run the bypass tests on a schedule.

Approval and denial workflow

Use two gates: the company's reviewed inventory change, then Microsoft's tenant approval for the preview Agent 365 server route. An approval in one gate does not replace the other. recommendation

Company governance

A requester adds the server, owner, sign-in, tools and risk class to the reviewed inventory in Git.

Security reviews the server and each of its tools.

Approval merges the change into the inventory. The pipeline then applies it to the policy targets.

Denial records the reason in Git and stops the request.

Preview pilot, after the baseline

  1. Scope. Pick a low-risk server with two read-only tools and one controlled write tool. Record owner, data class, sign-in and expected clients.
  2. Resource type. Create the separate AI Gateway product on the current resource type in a supported public preview region V45 V52 V195. Confirm eligibility, the public front door, networking, policy features and licensing.
  3. Lock the backend. Make direct calls fail. Check the supported backend network design, because the new gateway has no frontend private endpoints V47.
  4. Connect Agent 365. For the API Management integration, after named tenant-admin consent, connect the gateway and check that the server shows up. Review the permissions granted V40.
  5. Test blocking. For the preview Agent 365 integration, test server block/unblock on a supported API Management v2 tier. Test tool blocking and threat protection only on the separate AI Gateway product, with a static tool list and a delegated user-token flow V38 V53 V194. Test Audit, Block and failure handling.
